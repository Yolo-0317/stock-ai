# Tushare API 限流优化指南

## 🚨 问题说明

Tushare 免费账户的限流规则：
- **限制**：50 次/分钟
- **错误提示**：`抱歉，您每分钟最多访问该接口50次`

---

## ✅ 解决方案（已优化）

脚本已经内置了智能限流控制系统，具备以下特性：

### 1. **自动限流控制**
- 实时监控每分钟的 API 调用次数
- 接近阈值时自动等待
- 避免触发 Tushare 限流

### 2. **自动重试机制**
- 遇到限流错误自动等待 60 秒后重试
- 最多重试 3 次
- 其他错误使用指数退避策略

### 3. **实时进度显示**
```
[1234/5000] 000001.SZ （当前速率：42/45 次/分钟）
  ⏳ 已达限流阈值（45 次/分钟），等待 18.5 秒...
```

## 🔧 参数说明

### `--sleep` (API 调用间隔)

控制每次 API 调用后的等待时间。

```bash
# 1.5 秒（默认，平衡速度和稳定性）
--sleep 1.5

# 2.0 秒（推荐，更稳定）
--sleep 2.0

# 3.0 秒（最稳定，适合网络差的情况）
--sleep 3.0
```

**计算公式：**
- 理论最快：60 秒 / 50 次 = 1.2 秒/次
- 安全间隔：≥ 1.5 秒（留 20% 余量）
- 推荐间隔：2.0 秒（留 40% 余量）

### `--max-calls` (每分钟最大调用次数)

控制每分钟最多调用 API 的次数。

```bash
# 45 次（默认，留 10% 余量）
--max-calls 45

# 40 次（推荐，留 20% 余量）
--max-calls 40

# 30 次（保守，留 40% 余量）
--max-calls 30
```

**说明：**
- Tushare 限制：50 次/分钟
- 建议设置：40-45 次（留余量避免意外触发）
- 达到阈值时脚本会自动等待

## ❓ 常见问题

### Q1: 为什么默认间隔是 1.5 秒，而不是更快？

**A:** 
- 理论最快：1.2 秒/次（50 次/分钟）
- 实际需要考虑：
  - 网络延迟（可能 0.1-0.5 秒）
  - API 处理时间（不固定）
  - 系统时间精度（可能有误差）
- 1.5 秒是经过测试的平衡值

### Q2: 我能把间隔设置为 0.5 秒吗？

**A:** 不建议。
- 理论上 1.2 秒是极限
- 0.5 秒必定触发限流
- 触发限流后需要等待 60 秒，反而更慢

### Q3: 增量更新需要多久？

**A:** 取决于股票数量和配置：
- 5000 股 × 1.5 秒 = 125 分钟（默认配置）
- 5000 股 × 2.0 秒 = 167 分钟（推荐配置）
- 但增量更新通常只需更新部分股票（已是最新的会跳过）

### Q4: 如何加速同步？

**A:** 
1. **不推荐**：减少间隔（容易触发限流）
2. **推荐**：升级 Tushare 权限（付费用户限流更宽松）
3. **推荐**：使用 `--limit` 分批同步
4. **推荐**：只同步需要的股票（使用 `--codes`）
